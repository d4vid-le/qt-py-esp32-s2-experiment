# Gate 1 addendum — U$15 (ESP32-S2) pin audit

**Verdict: PASS. 57/57 pads map 1:1 to the ESP32-S2 QFN56 pin table. No
ambiguity remains. Gate 2 may proceed after human review.**

## Exact part number

**ESP32-S2FN4R2** — QFN56, 7×7 mm, 4 MB in-package flash + 2 MB in-package PSRAM.

Evidence:

| Source | What it confirms |
|---|---|
| Adafruit product 5325 | “ESP32-S2 mini-module … 4 MB flash and 2 MB PSRAM” |
| Espressif datasheet **v1.9**, ordering table | `ESP32-S2FN4R2` = 4 MB flash + 2 MB PSRAM, QFN56 |
| Espressif datasheet **v1.9**, package ch. 7 | separate QFN56 package drawing “for ESP32-S2FN4R2” |
| Adafruit-hosted datasheet **v1.1** | 57-pin table used for pin names/functions; **does not list FN4R2** |

The Adafruit-hosted V1.1 predates the FN4R2, which is why the current V1.9 was
used as a supplementary source. V1.9 was downloaded from
`documentation.espressif.com` and kept in `reference/assets/` (gitignored).

## Library discrepancy found (label only)

| Eagle field | Value | Reality |
|---|---|---|
| Symbol | `ESP-32-S2` | okay |
| Device | `QFN54` | **mislabelled** — no QFN54 exists in this family |
| Package | `QFN56_7X7` | correct: 56 pins + exposed pad = **57 pads** |
| Pads | 57, contiguous 1..57 | correct, no gaps or duplicates |

No electrical impact. Recorded as a source quirk.

## Nomenclature differences (all normalized, all match)

| Eagle | Datasheet | Count |
|---|---|---:|
| `IO0` … `IO46` | `GPIO0` … `GPIO46` | 26 |
| `MTD0` (zero) | `MTDO` (letter O) | 1 |
| `VDDA@0/@1/@2` | `VDDA` | 3 |
| `VDD3P3@0/@1` | `VDD3P3` | 2 |
| `GND@0` | `GND` | 1 |

The `@N` suffixes disambiguate repeated names inside one Eagle symbol; they are
not pin numbers.

## Cross-datasheet check

Parsed the 57-pin table from both PDFs independently:

- V1.1: 57 pins, sequential, functions extracted.
- V1.9: 56 numbered pins extracted from Table 2-1; **all 56 names match V1.1**.
- Pin 57 is the exposed pad (`GND`), listed in V1.1 and shown in the V1.9
  QFN56/FN4R2 package drawing rather than Table 2-1.

## FN4R2-specific pins

Pins 29–36 are the in-package flash/PSRAM interface. The datasheet says these
pins “are not recommended for other uses”.

| Pin | Name | Net in this design |
|---:|---|---|
| 29 | SPICS1 | unconnected |
| 30 | VDD_SPI | `VDD_SPI` (C12 0.1 µF + C13 1 µF only) |
| 31 | SPIHD | unconnected |
| 32 | SPIWP | unconnected |
| 33 | SPICS0 | unconnected |
| 34 | SPICLK | unconnected |
| 35 | SPIQ | unconnected |
| 36 | SPID | unconnected |

Leaving 29 and 31–36 unconnected is consistent with in-package memory. VDD_SPI
is deliberately isolated from 3.3 V — this is the Rev C low-power-sleep fix, and
the datasheet allows VDD_SPI to be an output/controlled rail.

## Ambiguities

**None blocking.** One documented limitation: the Adafruit-hosted datasheet
(V1.1) does not cover the FN4R2; the current Espressif V1.9 was used to confirm
the part number and pin numbering. Both agree on all 56 numbered pins.
